# 용어 사전 (Glossary)

> **목적**: 동료와 같은 언어로 말하기 위한 단일 사전. 코드를 읽을 때 "이 단어를 모르겠다"가 나오면 여기에 쌓는다.
> **원칙**: 한 줄 정의는 **내 말로** 쓴다. 남의 문장을 붙여넣으면 설명할 때 다시 막힌다.
> **관련**: 개념 단위의 긴 설명은 `general-concepts.md` / `phase1-concepts.md`. 여기는 **단어 단위**.

---

## 사용법

**① 수집 (학습 중)**
모르는 단어를 만나면 즉시 `상태 = 🔴` 로 이름만 적는다. 정의는 나중에. 흐름을 끊지 않는 게 더 중요하다.

**② 채우기 (미션 종료 전)**
🔴 항목을 표 형식으로 채운다. 5칸 전부 채워야 한다.

| 칸 | 왜 필요한가 |
|---|---|
| 한 줄 정의 | 동료평가에서 첫 문장으로 나가는 말 |
| 어원 / 왜 이 이름 | 이름을 알면 안 잊는다. 개발 용어 대부분은 영어 단어 그대로다 |
| 비유 | 상대가 못 알아들었을 때 꺼내는 두 번째 카드 |
| 내가 본 곳 | 파일:줄 또는 미션명. **추상적 암기를 막는 장치** |
| 헷갈리는 짝 | 비슷해서 섞이는 단어. 구분해서 말할 수 있어야 안다고 할 수 있다 |

**③ 상태 표기**

| 표기 | 뜻 |
|---|---|
| 🔴 | 이름만 안다 |
| 🟡 | 정의는 쓸 수 있으나 남에게 설명해본 적 없다 |
| 🟢 | 소리 내어 설명해봤고 막히지 않았다 |

> 🟢 판정 기준: **책/화면을 안 보고 30초 안에 정의 + 비유 + 실제 사례를 말할 수 있는가.**
> 이 기준을 통과한 것만 🟢. 스스로에게 후하면 동료평가에서 그대로 드러난다.

### A-1. 승급 완료 항목 (5칸 기입)

| 상태 | 용어 | 한 줄 정의 | 어원 / 왜 이 이름 | 비유 | 내가 본 곳 | 헷갈리는 짝 |
|---|---|---|---|---|---|---|
| 🟡 | `defer` 속성 (6) | 스크립트를 **HTML을 끝까지 다 읽은 뒤에** 실행하라는 지시 | defer = 미루다, 연기하다. 군 입대 유예 `draft deferment`와 같은 단어 | 학생이 **전원 착석한 뒤** 유인물을 돌리기. 먼저 돌리면 빈자리에도 놓게 됨 | B1-1 Phase 0 `index.html`:49 + 실험 1·2 | `async` (기다리지 않고 받는 즉시 실행) / 스크립트를 body 끝에 두기 (위치로 해결) |
| 🟡 | `null` (JS) | "값이 없음"을 뜻하는 값. `querySelector`가 요소를 못 찾으면 이걸 돌려준다 | null = 무효, 없음 (라틴어 nullus) | 빈 사물함. 사물함 자체는 있는데 안에 아무것도 없음 | Phase 0 실험 1 Console | `undefined` (아예 지정된 적 없음) |
| 🟡 | TypeError | 값의 **종류**가 기대와 달라서 나는 에러. 문법은 맞는데 값이 틀린 경우 | Type(종류) + Error | 우편함에 편지 대신 벽돌이 와서 열지 못하는 상황 | Phase 0 실험 1 | SyntaxError (문법 자체가 틀림) |

| 🟡 | 박스 모델 (8) | 모든 요소는 content → padding → border → margin 의 **네 겹 사각형**이다 | box(상자) + model(모형). 브라우저는 모든 요소를 상자로 보고 계산한다 | 액자 포장. 내용물(content) → 완충재(padding) → 액자틀(border) → 액자끼리 띄운 간격(margin) | A3 실습 `a3-box-model.html` | `padding`(배경색 칠해짐, 상자가 커짐) vs `margin`(투명, 이웃을 밀어냄) |
| 🟡 | `box-sizing` | `width`가 **무엇의 폭**을 가리키는지 정하는 속성 | box(상자) + sizing(치수 재는 법) | 양복 치수. 가슴둘레를 속옷 안으로 재느냐 겉옷 밖으로 재느냐 | A3 실험1 -- 같은 300px 설정에서 360 vs 300 | `content-box`(기본값, padding·border가 **밖으로** 붙음) vs `border-box`(**안으로** 파고듦) |
| 🟡 | margin 상쇄 (collapse) | 위아래로 맞닿은 형제의 **세로** margin은 더해지지 않고 큰 쪽 하나만 남는다 | collapse = 무너지다, 겹쳐지다 | 장문첩 두 장을 붙일 때 여백이 두 배가 아니라 한 번만 생김 | A3 실험2 -- 40+40 → 40 | **가로 margin은 상쇄되지 않는다** (40+40=80 그대로) |

> **`defer` 판정 근거**: 실험 1(head + defer 없음 → `null` 에러)과
> 실험 2(head + defer 있음 → 정상)를 직접 실행해 **위치를 고정한 채 defer만 바꿔** 확인했다.
>
> **`defer` 3문장 리허설 초안**
> ① 스크립트에 `defer`를 붙여 HTML을 다 읽은 뒤 실행되게 했습니다.
> ② 스크립트를 `head`에 두더라도 요소를 안전하게 찾을 수 있기 때문입니다.
> ③ 안 붙였다면 `querySelector`가 `null`을 반환해 `Cannot set properties of null` 에러가 났을 것입니다.

> **박스 모델 판정 근거 (2026-09-11)**: 예측 3개 중 2개 적중.
> Q1(offsetWidth 300/360) · Q2(margin 상쇄 40px)는 맞혔고,
> Q3(배경색이 칠해진 면적)을 **틀렸다**. `margin`이 더 넓다고 답했으나 정답은 `padding`이다.
> 오답 원인: "차지한 자리"와 "배경색이 칠해진 면적"을 동일시함. 실제로는 갈린다.
> **이 구분이 박스 모델의 핵심이다.** 버튼 클릭 영역을 키우려면 `padding`, 간격만 벌리려면 `margin`.
>
> ⚠ **실행 대조 보류**: A1·A2·A3 세 실습 파일을 아직 브라우저에서 열어보지 못했다.
> 예측과 해설만 마친 상태이므로 🟢 승급은 관찰 후로 미룬다.
