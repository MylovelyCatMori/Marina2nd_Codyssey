## Week1 Mission1: 개발 워크스페이스 구축

### 핵심 개념

#### 절대경로 vs 상대경로
- **절대경로**: 루트(/)부터 시작. 어디서든 동일한 위치를 가리킴. 예) `/home/user/docs/file.txt`
- **상대경로**: 현재 위치 기준. 예) `./docs/file.txt`, `../other/`
- **왜 중요한가**: Dockerfile, 스크립트에서 경로 오류의 90%가 이 차이에서 발생

#### 파일 권한 (r/w/x)
- `r=4`: 읽기, `w=2`: 쓰기, `x=1`: 실행
- `755 = rwxr-xr-x`: 소유자 모든권한 / 그룹+others 읽기+실행
- `644 = rw-r--r--`: 소유자 읽기+쓰기 / 그룹+others 읽기만
- **왜 중요한가**: 실행 파일에 x 없으면 Permission denied 오류

#### 디렉토리에서 x 권한의 의미
- 파일의 x = 파일 실행 권한
- **디렉토리의 x = 해당 폴더 안으로 cd(change directory)로 진입할 수 있는 권한**
- `chmod 644 docs/` → x 권한 제거 → `cd docs/` 시 `Permission denied` 발생
- 복구 명령: `chmod 755 docs/`
- r 권한만으로는 폴더 내부 탐색 불가. 반드시 x 필요.

#### Docker 핵심 개념
- **이미지(image)**: 실행 환경의 스냅샷. 불변(immutable).
- **컨테이너(container)**: 이미지로부터 실행된 인스턴스. 격리된 프로세스.
- **Docker의 목적**: 어떤 컴퓨터에서도 동일한 환경을 격리하여 실행. 실수해도 컨테이너 삭제로 초기화 가능.

#### 포트 매핑 (port mapping)
- `docker run -p 8080:80` → `호스트포트:컨테이너포트`
- 8080 = 호스트(내 컴퓨터) 포트 / 80 = 컨테이너 내부 포트
- 브라우저 접속 주소: `localhost:8080` (호스트 포트로 접속)
- 흐름: 브라우저 → localhost:8080 → 도커가 컨테이너:80으로 전달
- 컨테이너 포트(80)는 외부에서 직접 접속 불가. 반드시 호스트 포트 경유.

#### 바인드 마운트 vs 볼륨
| 구분 | 저장 위치 | 주 사용 목적 |
|------|-----------|------------|
| 바인드 마운트 | 호스트(내 컴퓨터)의 특정 경로 | 개발 환경 (파일 수정 즉시 반영) |
| 볼륨 | 도커가 관리하는 별도 공간 | 운영(production) 환경 (데이터 영속성) |

- 바인드 마운트: `-v /host/path:/container/path` → 호스트 파일 수정 시 컨테이너에 즉시 반영
- 볼륨: `-v myvolume:/container/path` → 컨테이너 삭제해도 데이터 보존
- **비유**: 바인드 마운트 = 집 서랍을 실험실로 끌어다 쓰기 / 볼륨 = 실험실 전용 잠금 보관함

#### Docker vs 클라우드 구분
- Docker = **도구** (컨테이너 실행 소프트웨어). 내 PC, 서버, 클라우드 어디서든 실행 가능.
- 클라우드 = **장소** (인터넷으로 빌려 쓰는 원격 컴퓨터 공간). AWS, GCP, Azure 등.
- Docker는 클라우드 위에서도 실행 가능. 클라우드는 Docker를 실행하는 인프라 중 하나.

#### Git vs GitHub
- **Git**: 로컬 버전 관리 시스템(VCS, Version Control System). 내 컴퓨터에서 파일 변경 이력 추적. 인터넷 없이 사용 가능.
- **GitHub**: Git 저장소를 인터넷에 올려 보관하는 원격 서비스. Microsoft 운영. 협업/백업/코드리뷰 기능 포함.
- 흐름: `내 컴퓨터(Git)` → push → `GitHub(원격)` / `GitHub` → pull → `내 컴퓨터`
- **비유**: Git = 일기장에 날짜별 기록 행위 / GitHub = 일기장을 클라우드에 백업하는 서비스

#### git config 범위 옵션
| 옵션 | 적용 범위 | 저장 위치 |
|------|-----------|-----------|
| `--global` | 내 컴퓨터의 모든 프로젝트 | 홈 디렉토리 |
| `--local` | 현재 프로젝트만 | `.git/config` |
| `--system` | 이 컴퓨터의 모든 사용자 | 시스템 설정 파일 |

- `user.name`, `user.email` 같은 신원 정보 → `--global`로 한 번만 설정
- 특정 프로젝트에서 다른 이름/이메일 필요 시 → `--local`로 덮어쓰기
