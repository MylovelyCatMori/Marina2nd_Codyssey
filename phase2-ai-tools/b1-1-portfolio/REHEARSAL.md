## 1. `status` 문자열 하나로 4상태 표현

**코드**: `js/main.js:40`, `249~279`

```js
repoState: { status: 'loading', data: [], error: null },
// 'loading' | 'success' | 'error' | 'empty'
```

1. **무엇**: GitHub 저장소 목록의 네 상태를 불리언 여러 개가 아니라 `status` 문자열 하나로 표현했다.
2. **왜**: 불리언 4개는 조합이 16가지 나오는데 말이 되는 건 4가지뿐이다. **나머지 12가지 불가능한 상태를 코드가 막아주지 못하고 개발자가 손으로 지켜야 한다.** 문자열은 값이 하나라 두 상태가 동시에 참이 될 수 없다.
3. **안 그랬으면**: 에러 처리에서 `isLoading`을 되돌리는 걸 잊으면 **에러가 났는데 로딩 스켈레톤이 계속 돈다.** 넷 다 꺼지면 아무것도 안 그려져 **빈 화면**이 나오고 사용자는 고장으로 본다.

> 검증: 반례 스크립트 실행으로 16가지 중 12가지가 불가능 조합임을 확인했다.

## 2. nav는 Flex, projects는 Grid

**코드**: `css/style.css:181`(nav), `480~482`(projects)

```css
.projects-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); }
```

1. **무엇**: nav는 Flex로, 프로젝트 카드 목록은 Grid로 배치했다.
2. **왜**: **Flex는 내용이 배치를 정하고 Grid는 틀이 배치를 정한다.** nav 항목은 글자 길이가 제각각이라 각자 필요한 만큼만 차지해야 하므로 내용이 주인인 Flex가 맞다. 카드는 개수가 몇 개든 서로 폭이 같아야 하므로 틀이 주인인 Grid가 맞다.
3. **안 그랬으면**: nav를 Grid로 하면 칸을 똑같이 나눠놓아 "홈"은 좌우가 휑하고 간격이 들쭉날쭉해 보인다. 카드를 Flex로 하면 **마지막 줄 카드가 남은 공간을 나눠 가져 위 줄보다 뚱뚱해지고 세로 정렬이 어긋난다.**

> 정밀 표현: Grid도 `1fr`이라 폭은 늘어난다. 고정된 것은 **"어느 순간에도 모든 카드 폭이 서로 같다"**이며, 창을 줄이면 열 개수가 3→2→1로 바뀔 뿐이다.
> 검증: 반례 HTML을 만들어 창 너비를 바꿔가며 네 경우를 직접 대조했다.

## 3. 필터에 `filter`와 `slice`만 사용

**코드**: `js/main.js:216~222`

```js
const filtered = AppState.activeLanguage === ALL
  ? data
  : data.filter((repo) => (repo.language || UNKNOWN_LANGUAGE) === AppState.activeLanguage);
return filtered.slice(0, MAX_VISIBLE_REPOS);
```

1. **무엇**: 언어 필터에서 원본 `data`를 건드리지 않고 `filter`와 `slice`로 새 배열만 만들었다.
2. **왜**: **원본 `data`가 단일 진실 출처이고 화면 목록은 거기서 파생된 결과다.** 파생물을 만들자고 원본을 고치면 다음 파생을 만들 수 없다.
3. **안 그랬으면**: `Python` 클릭 시 원본이 Python만 남고, 이어서 `JavaScript`를 누르면 **화면이 0건이 된다.** `전체`로 돌아가도 복구되지 않는다. **한 번만 눌러보면 멀쩡해 보이고 두 번째 클릭부터 무너진다.**

## 4. 재시도 버튼에 이벤트 위임

**코드**: `js/main.js:579`

```js
els.projectsGrid.addEventListener('click', (event) => { /* 올라온 클릭을 판별 */ });
```

1. **무엇**: 재시도 버튼에 직접 리스너를 걸지 않고 부모 `projectsGrid`에 걸어 올라온 클릭을 판별했다.
2. **왜**: 재시도 버튼은 **에러가 나야 생기고, 다시 그릴 때마다 새 DOM 노드로 교체된다.** 부모는 사라지지 않으므로 리스너가 유지된다.
3. **안 그랬으면**: ① 첫 로드 시점엔 버튼이 없어 `null`에 리스너를 걸다 에러가 난다. ② **재시도가 한 번은 먹고 두 번째부터 죽는다.** 에러 화면을 다시 그리면서 버튼이 새 노드로 바뀌기 때문이다.

## 5. 테마 전환을 CSS 변수로만

**코드**: `css/style.css` `:root` / `[data-theme="dark"]`, `js/main.js:369`

```js
document.documentElement.dataset.theme = 'dark';   // 이 한 줄이 전부
```

1. **무엇**: 요소마다 색을 JS로 바꾸지 않고 최상위 `data-theme` 속성 하나만 바꾸며, 색은 전부 CSS 변수로 처리했다.
2. **왜**: **JS는 실행되는 그 순간 화면에 있는 요소만 칠한다.** CSS 변수는 상속이라 나중에 만들어진 요소도 자동으로 물려받는다.
3. **안 그랬으면**: 다크모드를 켠 채 새로고침하면 배경은 검은데 **API로 뒤늦게 그려진 프로젝트 카드만 하얗게** 나온다.
