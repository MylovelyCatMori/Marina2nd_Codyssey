## 1. 제품 개요

### 한 줄 요약
외부 라이브러리 없이 순수 HTML/CSS/JavaScript만으로 만드는 반응형 개인 포트폴리오 웹사이트. GitHub 저장소를 실시간으로 불러와 Projects 섹션에 렌더링한다.

### 해결하는 문제
두 층의 문제를 동시에 푼다.

| 층 | 문제 |
|---|---|
| 겉 (제품) | 나를 소개할 공개 URL이 없다. 이력/기술스택/작업물이 흩어져 있어 한 번에 보여줄 곳이 없다 |
| 속 (학습) | React를 배우기 전에 **DOM 조작 · 이벤트 · 비동기**를 몸으로 익혀야 한다. 프레임워크가 대신 해주는 일을 손으로 해봐야 프레임워크가 왜 필요한지 안다 |

### 핵심 가치
**"이벤트 → 상태 변경 → DOM 업데이트" 흐름을 코드에서 눈으로 확인할 수 있는 것.**

과제 원문 7항이 명시한다 — "UI 고퀄리티보다 이벤트 → 상태 → 렌더링 흐름 이해 우선". 따라서 이 프로젝트의 성공은 예쁨이 아니라 **설명 가능성**으로 판정된다. 동료평가에서 "이 줄 지우면 어떻게 되나요?"에 답할 수 있어야 한다 (`LEARNING_RULES.md` 규칙 2).

### 이 프로젝트의 진짜 심사위원
1. **동료평가자** -- README와 코드를 보고 인터뷰 질문을 만든다
2. **나 자신** -- 3문장으로 설계 결정을 설명할 수 있어야 한다 (규칙 3)
3. **브라우저** -- 배포 URL에서 전 기능이 실제로 동작해야 한다

## 2. 사용자

### 주요 사용자
- **누구**: 나를 처음 보는 사람 (동료평가자, 채용 담당자, 커뮤니티 지인)
- **상황**: 링크 하나를 받아 모바일 또는 데스크톱 브라우저로 연다. 체류 시간은 짧다
- **목표**: "이 사람이 누구고 뭘 만들 줄 아는가"를 30초 안에 파악한다

### 2차 사용자
- **누구**: 동료평가자
- **상황**: README를 열어두고 코드와 대조하며 질문한다
- **목표**: 학습자가 자기 코드를 이해했는지 확인한다

### 사용자 시나리오

**시나리오 A -- 방문자 (해피패스)**
1. 방문자가 모바일에서 배포 URL을 연다
2. Hero 섹션의 인사말과 CTA 버튼 두 개가 보인다
3. "View Projects"를 누르면 Projects 섹션으로 부드럽게 스크롤된다
4. Projects 섹션에는 "로딩 중..." 이 잠깐 뜨고, GitHub 저장소 카드가 채워진다
5. 언어 필터 버튼으로 "Python"만 눌러 걸러본다
6. 우상단 토글로 다크모드를 켠다. 나중에 다시 들어와도 다크모드가 유지된다

**시나리오 B -- 방문자 (에러패스)**
1. 방문자가 새로고침을 여러 번 반복한다
2. GitHub API가 403(레이트 리밋)을 반환한다
3. Projects 섹션에 "프로젝트를 불러올 수 없습니다" + **[다시 시도]** 버튼이 표시된다
4. 잠시 후 재시도를 누르면 정상 로딩된다

**시나리오 C -- 동료평가자**
1. 평가자가 README의 "핵심 개념 정리" 섹션을 연다
2. "Flexbox와 Grid를 어디에 왜 나눠 썼나요?"를 묻는다
3. 학습자가 nav(Flexbox) / 카드 그리드(Grid)를 열고 3문장으로 답한다

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름
```
페이지 진입 -> 테마 복원 -> Hero 표시 -> GitHub API 호출
     -> [로딩] -> [성공: 카드] / [에러: 재시도] / [빈: 안내]
     -> 스크롤 탐색 -> 필터 조작 -> 폼 제출 -> 성공 메시지
```

### 상태 → 렌더링 흐름 4종 (과제 핵심 평가 포인트, F-56/F-57)

이 프로젝트에서 "상태"란 화면을 결정하는 JS 변수를 말한다. 아래 네 개가 각각 독립된 흐름이다.

**흐름 1 -- 테마**
```
[이벤트] 토글 버튼 click
   ↓
[상태]  theme = 'light' | 'dark'
   ↓
[렌더링] document.documentElement의 data-theme 속성 교체
        → CSS 변수 세트가 통째로 바뀜 → 전체 화면 색 변경
   ↓
[영속화] localStorage.setItem('theme', theme)
```
> **설계 의도**: 색을 JS로 하나하나 바꾸지 않는다. 속성 하나만 바꾸고 나머지는 CSS가 처리한다. 관심사 분리.

**흐름 2 -- 프로젝트 목록**
```
[이벤트] 페이지 로드 / [다시 시도] click
   ↓
[상태]  repoState = { status: 'loading'|'success'|'error'|'empty', data: [], error: null }
   ↓
[렌더링] renderProjects(repoState) 단 하나의 함수가 status로 분기하여 섹션을 다시 그림
```
> **설계 의도**: 상태를 객체 하나로 모으고 렌더 함수를 하나로 둔다. 이것이 React `useState` + 렌더링의 원리 그 자체다.

**흐름 3 -- 폼 유효성**
```
[이벤트] input 입력 / submit
   ↓
[상태]  formErrors = { name: '...', email: '...', message: '...' }
   ↓
[렌더링] 각 필드 아래 .error-text에 메시지 표시/숨김 + 필드 테두리 색 변경
```

**흐름 4 -- 언어 필터 (보너스)**
```
[이벤트] 언어 버튼 click
   ↓
[상태]  activeLanguage = 'All' | 'Python' | ...
   ↓
[렌더링] repoState.data.filter(...) 결과로 카드 목록 재렌더링
```
> **설계 의도**: 원본 데이터(`repoState.data`)를 절대 변형하지 않는다. 필터는 파생 결과다. 원본을 지우면 "All"로 되돌릴 수 없다.

## 6. 안 만드는 것 (Out of Scope)

> AI에게 코드를 시킬 때 이 목록을 반드시 함께 공유한다.

| 안 만드는 것 | 이유 |
|---|---|
| 빌드 도구 (Vite, webpack, npm 스크립트) | 과제가 요구하지 않는다. `index.html`을 브라우저가 바로 읽는 구조가 학습 목적에 맞다 |
| CSS 전처리기 (Sass, PostCSS) | 컴파일 단계가 생기면 "브라우저가 이해하는 유일한 언어"라는 미션 전제가 흐려진다 |
| 프레임워크 / UI 라이브러리 | **C-01 위반 = 과제 무효** |
| 백엔드 서버 / 데이터베이스 | GitHub Pages는 정적 호스팅이다. 서버가 없다 |
| 로그인 / 회원가입 | 요구사항에 없다. 인증은 후속 미션(B6-3) 대상이다 |
| 다국어(i18n) | 요구사항에 없다. 상태 관리 복잡도만 늘린다 |
| GitHub 토큰 인증 | 토큰을 정적 사이트에 넣으면 그대로 노출된다. 미인증 60회/시 제한을 **에러 UI로 처리**하는 것이 과제 요구(F-55)다 |
| 커스텀 도메인 연결 | 과제는 GitHub Pages URL만 요구한다. TODO.md의 "도메인 연결"은 과제 원문에 근거가 없어 제외 |
| 자동화 테스트 프레임워크 | 과제에 없다. 검증은 수동 체크리스트 + 금지패턴 grep으로 대체 |
