## 1. 제품 개요

### 한 줄 요약

터미널에서 명령어로 수입·지출을 기록하고, 월별로 요약하며, 예산 초과를 경고해 주는
**파일 기반 콘솔 가계부**입니다.

### 해결하는 문제

가계부 앱은 많지만 대부분 계정 가입과 네트워크를 요구합니다. 이 프로그램은
**설치도 가입도 없이** 파이썬만 있으면 돌아가고, 데이터는 내 컴퓨터의 CSV 파일로만
남습니다.

다만 과제로서의 진짜 목적은 기능이 아닙니다. 원문 1번이 이렇게 못 박고 있습니다.

> "'작은 서비스'란 기능이 많은 게 아니라 **예외 상황에서도 데이터가 안전한 것**을
> 말합니다."

즉 이 과제가 묻는 것은 **"돌아가는가"가 아니라 "망가지지 않는가"** 입니다.

### 핵심 가치

| 가치 | 의미 |
|---|---|
| **데이터 안전성** | 저장 중 프로그램이 죽어도 파일이 반쪽으로 남지 않는다 |
| **메모리 안전성** | 파일이 아무리 커도 한 번에 다 읽지 않는다 (제너레이터 스트리밍) |
| **구조 분리** | 모델 / 저장소 / 서비스 / CLI 네 계층의 책임이 섞이지 않는다 |
| **계약 명시** | 타입 힌트로 함수의 입출력 약속을 코드에 적는다 |
| **오류 친절성** | 스택트레이스 대신 **원인 + 해결 힌트**를 보여준다 |

## 2. 사용자

### 주요 사용자

| 구분 | 설명 |
|---|---|
| **1차 사용자** | 과제 작성자 본인. 터미널 사용에 익숙하며 자기 지출을 기록하려는 사람 |
| **2차 사용자** | 동료평가자. 48시간 내에 이 프로그램을 받아 실행하고 질문을 던진다 |

2차 사용자의 존재가 설계에 영향을 줍니다. **처음 받은 사람이 README만 보고 3분 안에
실행할 수 있어야 합니다.** 그래서 초기 실행 시 데이터 파일과 기본 카테고리를 자동으로
만들어 주는 쪽을 택했습니다.

### 사용자 시나리오

**시나리오 1 — 매일의 기록**

> 점심을 먹고 15,000원을 썼다. 터미널을 열고 `add`를 실행한다. 날짜, 타입, 카테고리,
> 금액, 메모를 차례로 묻는다. 엔터를 다섯 번 치면 `[저장 완료] id=TX-000012`가 나온다.

**시나리오 2 — 월말 점검**

> 이번 달을 돌아본다. `summary --month 2026-09 --top 3`을 친다. 총수입, 총지출,
> 잔액이 나오고, 지출이 많았던 카테고리 3개가 순위로 보인다. 예산을 걸어 두었다면
> 사용률과 초과 경고가 함께 뜬다.

**시나리오 3 — 잘못 적었을 때**

> 금액을 15,000이 아니라 1,500으로 적었다. `update --id TX-000012`를 실행하면 현재 값이
> 번호와 함께 보인다. 4번(금액)을 고르고 새 값을 넣는다. 저장은 임시 파일에 쓴 뒤
> 원본과 교체되므로, 중간에 창을 닫아도 원본이 깨지지 않는다.

**시나리오 4 — 동료평가**

> 평가자가 저장소를 받는다. README를 보고 `python -m budget_app --help`를 친다.
> 명령 목록이 나온다. `add`를 해 보니 카테고리가 자동으로 만들어져 있어 바로 입력된다.
> `category remove food`를 시도하니 사용 중이라 막힌다. 오류 메시지에 해결 방법이 적혀
> 있다.

## 3. 핵심 기능

> 원문 2번 "최종 결과물"의 10개 기능은 **전부 필수**입니다. 선택 사항이 아닙니다.

| # | 명령 | 하는 일 | 입력 방식 | 복잡도 |
|---|---|---|---|---|
| 1 | `add` | 거래 추가 | **대화형** | 보통 |
| 2 | `list` | 최신순 목록 | 옵션 (`--limit`) | 보통 |
| 3 | `search` | 조건 검색 | 옵션 (5종) | 보통 |
| 4 | `summary` | 월별 요약 + 예산 경고 | 옵션 (`--month`, `--top`) | 복잡 |
| 5 | `budget set` | 월 예산 저장 | 옵션 | 간단 |
| 6 | `category add/list/remove` | 카테고리 관리 | 혼합 | 보통 |
| 7 | `update` | 거래 수정 | **대화형 (고정)** | 복잡 |
| 8 | `delete` | 거래 삭제 | 옵션 (`--id`) | 보통 |
| 9 | `import` | CSV 일괄 등록 | 옵션 (`--from`) | 복잡 |
| 10 | `export` | 조건부 CSV 저장 | 옵션 (`--out` + 기간) | 보통 |

### 보너스 기능 (4종 전부 채택)

| 기능 | 이유 |
|---|---|
| **저장 원자성 강화** | 원문 4번이 이미 "권장"으로 적어둔 항목. 사실상 준필수 |
| **출력 테이블 정렬** | 포맷터를 별도 모듈로 분리하면 모듈화 요구에도 기여 |
| **백업 기능** | `backup` 명령으로 타임스탬프 복사본 생성 |
| **반복 내역** | 월세·월급 등록 후 특정 월에 자동 생성 |

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름

```
[터미널]
   │
   ├─ python -m budget_app --help ──→ 명령 목록
   │
   ├─ add ──→ 대화형 입력 ──→ 검증 ──→ 저장 ──→ id 출력
   │              ↑              │
   │              └──── 실패 시 재입력 요구
   │
   ├─ list / search ──→ 제너레이터 스트리밍 ──→ 최신순 테이블 출력
   │
   ├─ update / delete ──→ 임시 파일 작성 ──→ os.replace 교체
   │
   ├─ summary ──→ 스트리밍 집계 ──→ 예산 조회 ──→ 사용률/경고 출력
   │
   └─ import / export ──→ CSV 스키마 검증 ──→ 처리 건수 출력
```

### 상세 흐름 — `add` (대화형)

```
1. 카테고리 파일 확인
   └─ 비어 있으면 기본 카테고리 5종 자동 생성 + 안내 출력
2. 날짜 입력      → YYYY-MM-DD 형식 검증 → 실패 시 재입력
3. 타입 입력      → income / expense 만 허용 → 실패 시 재입력
4. 카테고리 입력   → 등록 목록에 있는지 확인 → 없으면 목록 보여주고 재입력
5. 금액 입력      → 양수 정수 검증 → 실패 시 재입력
6. 메모 입력      → 선택 (엔터로 건너뜀)
7. 태그 입력      → 선택, 쉼표 구분
8. id 채번        → TX-000001 형식, 기존 최대값 + 1
9. 파일에 append  → 한 줄 추가
10. [저장 완료] id=TX-000012 출력, 종료 코드 0
```

### 상세 흐름 — `summary` (예산 연동)

```
1. --month 파싱 (YYYY-MM)
2. transactions.csv 를 스트리밍으로 읽으며 해당 월만 누적
   ├─ 총수입, 총지출
   └─ 카테고리별 지출 합계 (dict 누적)
3. 데이터가 0건이면 "데이터 없음" 출력 후 종료 (종료 코드 0)
4. 잔액 = 총수입 - 총지출
5. budgets.csv 에서 해당 월 예산 조회
   ├─ 있으면: 사용률 = 총지출 / 예산 × 100
   │          100% 초과 시 경고 문구 추가
   └─ 없으면: 예산 줄 자체를 출력하지 않음
6. 카테고리별 지출을 내림차순 정렬, 상위 N개 출력
```

## 5. 성공 기준

| 기준 | 측정 방법 |
|---|---|
| 10개 명령이 전부 동작 | 각 명령을 실제 실행해 결과 확인 |
| `--help`가 모든 명령에 존재 | `python -m budget_app <cmd> --help` 11회 실행 |
| 저장 파일 3개 분리 | `data/` 폴더에 transactions / categories / budgets |
| 스트리밍 처리 | `list`, `search`, `summary`에 `readlines()` / 전체 `list()` 없음 |
| 데코레이터 1개 이상 실제 적용 | `@` 로 시작하는 적용 지점 존재 |
| 타입 힌트 | 모든 public 함수의 인자·반환에 타입 명시 |
| 모듈 3개 이상 | 파일 분리 확인 |
| 스택트레이스 0건 | 모든 오류 상황에서 traceback 미출력 |
| 종료 코드 | 정상 0 / 오류 0 이외 |
| 클래스 2개 이상 | dataclass + 저장소 클래스 |

## 6. 안 만드는 것 (Out of Scope)

| 안 만드는 것 | 이유 |
|---|---|
| GUI / 웹 화면 | 원문이 콘솔 프로그램으로 한정 |
| 데이터베이스 (SQLite 포함) | 원문 7번: 파일 저장 (JSONL 또는 CSV) |
| 외부 라이브러리 (pandas, rich, click 등) | 원문 7번: 표준 라이브러리만 |
| 다중 사용자 / 로그인 | 단일 사용자 로컬 프로그램 |
| 통화 환산, 자산 관리, 투자 추적 | 요구사항에 없음 |
| 실시간 동기화 / 클라우드 | 로컬 파일 저장만 |

> **로그인이 필요 없는 이유**: 데이터가 내 컴퓨터의 `./data` 폴더에만 존재하고
> 네트워크를 전혀 쓰지 않습니다. 인증할 대상 자체가 없습니다.

## 7. 결정된 선택지 (원문이 택일을 요구한 항목)

원문이 "둘 중 하나를 골라 문서에 명확히 고정하라"고 지시한 항목들입니다.

| 항목 | 결정 | 근거 |
|---|---|---|
| **저장 포맷** | **CSV** | import/export 스키마와 형식이 같아 변환 코드가 줄어든다. 동료평가 때 데이터를 바로 보여줄 수 있다 |
| **`update` 입력 방식** | **대화형** | `add`와 입력 흐름이 같아 일관적이다. 현재 값을 보면서 고칠 수 있다 |
| **초기 카테고리** | **기본 카테고리 자동 생성** (안 A) | 처음 받은 사람이 바로 `add`할 수 있다. 기본값: `food` `transport` `rent` `salary` `etc` |
| **사용 중 카테고리 삭제** | **삭제 차단** | 데이터 정합성이 절대 깨지지 않는다. 구현도 단순하다 (건수만 세면 됨) |
| **보너스 과제** | **4종 전부 채택** | 원자성은 원문이 이미 권장, 나머지 3종도 전부 수행 |

### CSV 선택에 따른 추가 처리

CSV는 모든 값이 문자열입니다. 그래서 다음 세 가지를 반드시 처리해야 합니다.

| 문제 | 처리 |
|---|---|
| `amount`가 문자열로 읽힘 | 읽을 때 `int()` 변환, 실패 시 해당 행을 건너뛰고 경고 |
| `tags`가 쉼표 구분인데 CSV 구분자도 쉼표 | 파이썬 `csv` 모듈이 따옴표로 감싸 처리. **직접 `split(',')` 금지** |
| 메모에 쉼표·줄바꿈 포함 가능 | 같은 이유로 `csv` 모듈 사용 강제 |
