> 생성일: 2026-09-17
> 참고: B1-1에서 검증된 방식(Phase별 feature 브랜치 → `--no-ff` 병합)을 그대로 따른다.

## 분리 원칙

B1-1과 달리 이 미션은 **화면이 없습니다.** 대신 데이터가 파일에 남습니다.
그래서 Phase를 나누는 기준도 다릅니다.

| B1-1 기준 | B2-1 기준 |
|---|---|
| 보이는 것 → 움직이는 것 → 데이터 | **읽기 → 쓰기 → 집계 → 입출력** |

**핵심 순서는 "읽기가 먼저"입니다.** 쓰기부터 만들면 잘못 쓴 데이터를 확인할 방법이
없습니다. `list`가 되어야 `add`가 제대로 됐는지 눈으로 볼 수 있습니다.

- [ ] `.gitignore` (Python용, `data/` 포함 여부 결정)

### 완료 기준

```bash

python -m budget_app add --help      # add 설명 출력
echo $?                              # 0
```

### 학습 포인트

**`python -m budget_app`가 왜 되는가** — `budget_app/__main__.py`가 있으면
`-m` 옵션으로 패키지를 실행할 수 있습니다. `python budget_app/main.py`와 달리
**import 경로가 깨지지 않습니다.**

## Phase 1: 모델 + 저장소 + 읽기 (1일)

### 목표

데이터를 읽어서 보여줄 수 있다. 아직 쓰지는 못한다.

### 작업

- [ ] `models.py` — `Transaction`, `Category`, `Budget` dataclass + 타입 힌트
- [ ] `storage.py` — `TransactionRepository`, `CategoryStore`, `BudgetStore`
  - [ ] `ensure_files()` — 파일 없으면 헤더만 있는 CSV 생성
  - [ ] 기본 카테고리 5종 자동 생성 (`food` `transport` `rent` `salary` `etc`)
  - [ ] **`stream()` 제너레이터** — `yield`로 한 건씩
- [ ] `formatter.py` — 테이블 정렬 출력 (보너스)
- [ ] `list` 명령 구현 (`--limit`, 기본 20, 최신순)
- [ ] 손으로 만든 샘플 CSV로 동작 확인

### 완료 기준

```bash
python -m budget_app list --limit 3
# TX-000012 | 2024-01-15 | expense | food      |    15,000 | 점심
```

### 검증

- [ ] `data/` 폴더와 CSV 3개가 자동 생성되는가
- [ ] 파일이 비어 있을 때 "데이터 없음" 안내가 나오는가
- [ ] `readlines()` / `list(reader)` 사용 0건 (grep)

### 학습 포인트 (5줄)

**제너레이터** — `return` 대신 `yield`를 쓰면 함수가 값을 하나 주고 **그 자리에서
멈춥니다.** 다음 값을 요청하면 멈춘 지점부터 이어서 실행합니다. 파일 전체를 메모리에
올리지 않으므로 파일이 아무리 커도 메모리 사용량이 같습니다.

## Phase 2: 쓰기 + 검증 + 데코레이터 (1.5일)

### 목표

거래를 추가·수정·삭제할 수 있다. 잘못된 입력은 막힌다.

### 작업

- [ ] `validators.py` — 날짜 / 타입 / 금액 / 카테고리 검증
- [ ] `decorators.py` — **공통 관심사 분리 (원문 필수)**
  - [ ] `@handle_errors` — 예외를 잡아 `원인 + 힌트`로 출력, 종료 코드 설정
  - [ ] `@log_call` — 실행 로그 (파일 또는 stderr)
  - [ ] `@measure_time` — 실행 시간 측정
- [ ] `add` — 대화형 입력 + 재입력 루프 + id 채번
- [ ] `delete --id` — 없는 id 처리
- [ ] `update --id` — **대화형 (문서 고정)**, 현재 값 표시 후 번호 선택
- [ ] **원자적 교체** — 임시 파일 + `os.replace` (보너스, update/delete 공통)

### 완료 기준

```bash
python -m budget_app add
# 날짜(YYYY-MM-DD): 2024-13-40
# [오류] 날짜 형식이 올바르지 않습니다 (YYYY-MM-DD).
# [힌트] 예: 2024-01-15
# 날짜(YYYY-MM-DD): _        ← 재입력 요구
```

### 검증

- [ ] 잘못된 날짜 / 음수 금액 / 0원 / 없는 카테고리 / 잘못된 타입 5종 차단
- [ ] 없는 id로 `delete` → 메시지 출력 + 종료 코드 0 이외
- [ ] 스택트레이스 0건
- [ ] `update` 중간에 강제 종료 → 원본 파일 무손상 확인

### 학습 포인트 (5줄)

**데코레이터** — 함수를 감싸서 앞뒤에 공통 동작을 끼워 넣는 문법입니다.
`@handle_errors`를 붙이면 그 함수 안에서 난 예외를 **함수를 고치지 않고** 일괄
처리할 수 있습니다. 명령이 10개인데 각각에 `try/except`를 쓰면 같은 코드가 10번
반복됩니다.

## Phase 3: 검색 + 집계 + 예산 (1.5일)

### 목표

쌓인 데이터에서 의미를 뽑아낸다.

### 작업

- [ ] `search` — `--from` `--to` `--category` `--type` `--q` `--tag` 5종 조건
  - [ ] 조건 조합 (AND) 처리
  - [ ] **스트리밍 유지** (필터를 제너레이터 안에서)
- [ ] `budget set --month --amount` — 저장 + 같은 달 덮어쓰기
- [ ] `summary --month --top N`
  - [ ] 총수입 / 총지출 / 잔액
  - [ ] 카테고리별 지출 TOP N
  - [ ] 예산 있으면 사용률 + 초과 경고
  - [ ] 데이터 없는 달 → "데이터 없음"
- [ ] `category add/list/remove` — **사용 중이면 삭제 차단**

### 완료 기준

```bash
python -m budget_app summary --month 2024-01 --top 3
# 총 수입: 3,000,000원
# 총 지출:   215,000원
# 잔액:    2,785,000원
# 예산:      500,000원 (사용률 43.0%)
```

### 검증

- [ ] 예산 초과 시 경고 문구 출력
- [ ] 예산 미설정 달 → 예산 줄 자체가 안 나옴 (0으로 나누기 없음)
- [ ] 데이터 없는 달 → "데이터 없음"
- [ ] 사용 중 카테고리 삭제 시 건수 + 해결 힌트 출력, 종료 코드 0 이외

### 학습 포인트 (5줄)

**집계와 스트리밍의 공존** — 전체를 다 봐야 합계가 나오는데 어떻게 스트리밍인가?
합계를 담는 변수 하나만 들고 **한 줄씩 더하면서 지나갑니다.** 메모리에 남는 것은
거래 목록이 아니라 누적된 숫자 몇 개뿐입니다.

### 학습 포인트 (5줄)

**왜 실패 행을 건너뛰고 계속하는가** — 100행 중 3행이 잘못됐다고 전부 거부하면
사용자는 3행을 찾아 고칠 방법이 없습니다. 97행을 넣고 **어느 행이 왜 빠졌는지**
알려주는 쪽이 낫습니다. 단, 건너뛴 건수는 반드시 출력합니다.

## Phase 1 시작 프롬프트

> Phase 0이 끝난 상태에서 이어서 진행한다.
> `models.py`에 `Transaction` / `Category` / `Budget`을 dataclass로 정의하고,
> `storage.py`에 세 저장소 클래스를 만든다. 읽기는 반드시 `yield` 기반 제너레이터로
> 구현하고 `readlines()`나 `list(reader)`는 쓰지 않는다. 파일이 없으면 헤더만 있는
> CSV를 만들고, 카테고리가 비어 있으면 기본 5종을 생성한 뒤 안내를 출력한다.
> 마지막으로 `list --limit N`을 최신순으로 출력한다.
