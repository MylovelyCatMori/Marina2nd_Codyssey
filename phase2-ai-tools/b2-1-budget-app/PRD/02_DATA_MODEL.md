## 엔티티 상세

### 1. Transaction (거래)

`dataclass`로 정의합니다. 이 프로그램에서 유일하게 계속 늘어나는 데이터입니다.

| 필드 | 타입 | 필수 | 설명 | 검증 규칙 |
|---|---|---|---|---|
| `id` | `str` | O | 거래 고유 번호 | `TX-` + 6자리. 파일 내 최대값 + 1 |
| `date` | `str` | O | 거래 날짜 | `YYYY-MM-DD`. `datetime.strptime`으로 실제 존재하는 날짜인지 확인 |
| `type` | `str` | O | 수입/지출 | `income` 또는 `expense` 만 허용 |
| `category` | `str` | O | 분류 | 등록된 카테고리 목록에 존재해야 함 |
| `amount` | `int` | O | 금액 | **양수 정수**. 0과 음수 거부 |
| `memo` | `str` | X | 메모 | 기본값 `""` |
| `tags` | `list[str]` | X | 태그 | 기본값 `[]`. CSV에는 쉼표 구분 문자열로 저장 |

**CSV 저장 형태**

```csv
id,date,type,category,amount,memo,tags
TX-000012,2024-01-15,expense,food,15000,점심,meal
TX-000011,2024-01-14,income,salary,3000000,,
TX-000010,2024-01-12,expense,food,8000,"김밥, 라면","meal,quick"
```

> 세 번째 행을 보십시오. 메모에 쉼표가 있고 태그가 두 개입니다. 둘 다 따옴표로
> 감싸여 있습니다. **`csv` 모듈이 자동으로 처리합니다.** 직접 `split(',')`을 쓰면
> 이 행에서 즉시 깨집니다.

**날짜를 `str`로 두는 이유** — `date` 객체로 두면 파일에 쓸 때마다 변환해야 하고,
정렬·비교도 문자열 상태에서 정확히 동작합니다. `YYYY-MM-DD`는 **사전순 정렬 = 시간순
정렬**이 성립하는 형식입니다.

### 2. Category (카테고리)

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `name` | `str` | O | 카테고리명. 중복 불가 |

**CSV 저장 형태**

```csv
name
food
transport
rent
salary
etc
```

**기본값** — 파일이 없거나 비어 있으면 위 5종을 자동 생성하고 안내를 출력합니다.

**삭제 규칙** — 해당 카테고리를 쓰는 거래가 **한 건이라도 있으면 삭제를 차단**합니다.
건수와 해결 방법을 함께 알려줍니다.

---

### 3. Budget (예산)

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `month` | `str` | O | `YYYY-MM`. 중복 불가 (같은 달 재설정 시 덮어쓰기) |
| `amount` | `int` | O | 양수 정수 |

**CSV 저장 형태**

```csv
month,amount
2024-01,500000
2024-02,450000
```

**`summary`와의 관계** — 예산은 `summary`에서만 읽힙니다.

```
사용률(%) = 해당 월 총지출 ÷ 예산 × 100
초과 여부 = 총지출 > 예산
```

예산이 없는 달은 **예산 줄 자체를 출력하지 않습니다.** "예산 0원"으로 표시하면
사용률이 무한대가 되거나 0으로 나누기 오류가 납니다.

---

### 4. RecurringRule (반복 내역, 보너스)

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | `str` | O | `RC-` + 4자리 |
| `day` | `int` | O | 매월 며칠 (1~28). **29~31 금지** |
| `type` | `str` | O | `income` / `expense` |
| `category` | `str` | O | 등록된 카테고리 |
| `amount` | `int` | O | 양수 정수 |
| `memo` | `str` | X | 메모 |

> **`day`를 1~28로 제한하는 이유** — 2월은 28일까지입니다. 31일로 등록하면 2월에
> 생성할 수 없습니다. "말일로 당긴다" 같은 규칙을 넣으면 그 자체가 또 하나의 예외
> 처리 대상이 됩니다. 입력 단계에서 막는 쪽이 단순합니다.

## 관계

```
Category ──(1:N)── Transaction
   │
   └─ 삭제 차단 조건: 참조하는 Transaction 이 1건 이상이면 삭제 불가

Budget ──(1:1 per month)── (summary 집계 결과)
   │
   └─ 실제 외래키는 없다. 조회 시점에 month 문자열로 맞춰본다

RecurringRule ──(생성)──> Transaction
   │
   └─ 생성된 거래는 일반 거래와 구분되지 않는다 (memo 로만 표시)
```

**외래키 제약이 파일에는 없습니다.** CSV는 무결성을 강제할 수단이 없으므로
**서비스 계층이 그 역할을 대신합니다.** 이것이 저장소(Repository)와 서비스(Service)를
나누는 실질적 이유입니다.

## 왜 이 구조인가

### 왜 `dataclass`인가

```python
@dataclass
class Transaction:
    id: str
    date: str
    type: str
    category: str
    amount: int
    memo: str = ""
    tags: list[str] = field(default_factory=list)
```

dict로 다루면 `tx["amont"]`처럼 오타를 내도 실행 전까지 모릅니다. dataclass는
필드 이름이 코드에 박혀 있어 에디터가 바로 잡아 줍니다. `__init__`, `__repr__`,
`__eq__`도 자동으로 생깁니다.

> `field(default_factory=list)`를 쓰는 이유 — `tags: list = []`로 쓰면 **모든
> 인스턴스가 같은 리스트 하나를 공유합니다.** 파이썬의 유명한 함정입니다.

### 왜 저장소를 클래스로 분리하는가

파일을 읽고 쓰는 법(어떤 인코딩, 어떤 구분자, 어떤 경로)은 **서비스가 알 필요가 없는
정보**입니다. 나중에 JSONL로 바꾸거나 SQLite로 옮기더라도 저장소 클래스 내부만
고치면 됩니다.

### 왜 제너레이터인가

```python
def stream(self) -> Iterator[Transaction]:
    with open(self.path, newline="", encoding="utf-8") as f:
        for row in csv.DictReader(f):
            yield self._to_transaction(row)
```

`readlines()`나 `list(reader)`는 **파일 전체를 메모리에 올립니다.** 거래가 10만 건이면
10만 건이 전부 올라갑니다. `yield`는 한 줄씩 꺼내 주므로 **파일 크기와 무관하게
메모리 사용량이 일정**합니다.

`list --limit 3`을 실행하면 세 줄만 읽고 멈출 수도 있습니다.

### 왜 원자적 교체인가

```python
tmp = path.with_suffix(".tmp")
with open(tmp, "w", ...) as f:
    ...쓰기...
os.replace(tmp, path)   # 이 한 줄이 원자적이다
```

원본에 직접 쓰는 도중 프로그램이 죽으면 **파일이 반쪽으로 남습니다.** 임시 파일에
전부 쓴 뒤 마지막에 이름을 바꾸면, 교체는 성공하거나 실패하거나 둘 중 하나입니다.
중간 상태가 없습니다.
