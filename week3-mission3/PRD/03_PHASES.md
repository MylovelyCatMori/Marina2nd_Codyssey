## Phase 1: 연산 코어 (반나절)

### 목표

Phase 1이 끝나면, 콘솔 UI 없이도 **MAC 점수 계산과 판정이 정확한지** 검증할 수 있다. 이후 모든 기능이 이 위에 올라간다.

### 기능

- [ ] `Matrix` 클래스 -- `from_rows` / `get` / `set` / `size` / `same_size_as`
- [ ] `normalize_label()` -- `+`,`cross` -> `Cross` / `x` -> `X` / 그 외 `None`
- [ ] `mac(a, b)` -- 이중 반복문, 외부 라이브러리 없음, float 반환
- [ ] `decide(score_a, score_b, label_a, label_b)` -- epsilon 기반 동점 처리
- [ ] `measure_mac_ms(a, b, repeat)` -- `time.perf_counter()` 기반 10회 평균 ms
- [ ] 상수: `EPSILON = 1e-9`, `REPEAT = 10`, 3x3 내장 Cross/X 필터·패턴

### 데이터

- `Matrix` (프로그램 내부), 3x3 내장 상수. 아직 data.json은 읽지 않는다

### 검증 방법 (실행 가능한 자체 점검)

- [ ] 3x3 십자 필터 x 3x3 십자 패턴 = `5.0`
- [ ] 3x3 X 필터 x 3x3 십자 패턴 = `1.0`
- [ ] `decide(0.9, 0.8999999999999999)` -> `UNDECIDED`
- [ ] `normalize_label("+") == "Cross"`, `normalize_label(" X ") == "X"`, `normalize_label("?") is None`
- [ ] `Matrix.from_rows([[1,2],[3]])` 가 `ValueError`를 일으키고, 호출한 쪽(`judge_case`)이 이를 잡아 케이스 단위 FAIL로 흡수

> 이 점검은 `python main.py --selftest` 한 줄로 돌아간다. 테스트 프레임워크는 쓰지 않는다 (외부 라이브러리 금지 + 제출물은 main.py 단일 파일).

## Phase 2: 모드 1 -- 사용자 입력 (반나절)

### 전제 조건

- Phase 1 자체 점검 전부 통과

### 목표

사람이 키보드로 3x3 필터 2개와 패턴을 넣으면 점수/시간/판정이 나온다. 잘못 입력해도 프로그램이 죽지 않는다.

### 기능

- [ ] `read_matrix(name, size)` -- 이름과 크기를 받아 한 줄씩 수집
- [ ] 행 개수 검증 -- 지정 행 수만큼 채울 때까지 반복
- [ ] 열 개수 검증 -- `입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.` 안내 후 **그 줄만** 재입력
- [ ] 숫자 파싱 검증 -- `float()` 실패 시 동일 안내 후 재입력
- [ ] 필터 A/B 입력 후 **저장 확인 출력** (요구사항 실행 흐름의 "저장 확인")
- [ ] MAC 결과 출력 -- A 점수 / B 점수 / 평균 연산 시간(ms) / 판정(A/B/판정 불가)
- [ ] 3x3 성능표 출력

### 검증 방법

- [ ] 예시 입력(십자 필터 A, X 필터 B, X 패턴)으로 A=1.0, B=5.0, 판정 B
- [ ] `1 2` 입력 -> 안내 후 재입력 요구, 프로그램 유지
- [ ] `a b c` 입력 -> 안내 후 재입력 요구, 프로그램 유지
- [ ] 빈 줄 입력 -> 안내 후 재입력 요구
- [ ] Ctrl+C / EOF -> 트레이스백 없이 메뉴 복귀 또는 안내 후 종료

## Phase 3: 모드 2 -- JSON 분석 + 성능 + 리포트 (하루)

### 전제 조건

- Phase 2 정상 동작

### 목표

data.json 6건을 일괄 판정하고, 실패를 숨기지 않고 사유와 함께 요약한다. 데이터가 망가져도 프로그램은 끝까지 간다.

### 기능

- [ ] `load_data(path)` -- 파일 없음 / JSON 파싱 실패 / 최상위 키 누락을 각각 구분해 안내 후 메뉴 복귀
- [ ] `parse_case_size(case_id)` -- `size_{N}_{idx}`에서 N 추출, 실패 시 케이스 FAIL
- [ ] 필터 로드 + 라벨 정규화 + 로드 완료 출력
- [ ] 케이스별: 필터 존재 확인 -> 크기 일치 검증 -> MAC 2회 -> 판정 -> expected 비교 -> PASS/FAIL
- [ ] 케이스 단위 예외 격리 -- 한 건이 깨져도 나머지는 계속 판정
- [ ] 성능 분석표 -- 3x3(내장) / 5x5 / 13x13 / 25x25, 각 10회 평균, 열 = 크기 / 평균 시간(ms) / 연산 횟수(N^2)
- [ ] 결과 요약 -- 총 테스트 / 통과 / 실패 + 실패 케이스 식별자와 사유

### 검증 방법

- [ ] 총 6 / 통과 3 / 실패 3 이 출력되고, 실패 3건이 `size_5_1`, `size_13_2`, `size_25_1`
- [ ] 실패 사유가 전부 `동점(UNDECIDED) 처리 규칙`
- [ ] data.json 파일명을 바꿔 숨긴 뒤 실행 -> 안내 메시지 후 메뉴 복귀 (트레이스백 없음)
- [ ] data.json 사본에서 `size_5_1.input` 행 하나를 지운 뒤 실행 -> 그 케이스만 FAIL, 나머지 5건 정상
- [ ] 성능표에서 25x25 평균 시간 / 5x5 평균 시간 비율이 대략 20~30배
