## 1. 제품 개요

### 한 줄 요약

컴퓨터가 그림의 "모양"을 어떻게 알아보는지를, NPU의 핵심 연산인 MAC(Multiply-Accumulate)을 외부 라이브러리 없이 직접 구현해 눈으로 확인하는 Python 콘솔 시뮬레이터.

### 해결하는 문제

사람은 십자가와 X를 순간적으로 구별하지만, 컴퓨터는 0과 1로 된 숫자 배열만 이해한다.
"컴퓨터가 모양을 인식한다"는 말이 실제로는 **필터와 입력을 위치별로 곱해서 전부 더한 점수 비교**라는 사실이, 설명만으로는 손에 잡히지 않는다.
이 시뮬레이터는 그 계산을 한 줄씩 눈에 보이게 만들어, 다음 세 가지를 체감시킨다.

1. 유사도 판정 = MAC 점수 비교라는 것
2. 필터가 커질수록 연산량이 N^2로 폭증한다는 것 (그래서 NPU가 필요하다는 것)
3. 실수(float) 연산은 수학적으로 같은 값도 미세하게 다르게 나온다는 것 (그래서 허용오차 정책이 필요하다는 것)

### 핵심 가치

| 항목 | 내용 |
|------|------|
| 라이브러리 금지 | NumPy 없이 이중 반복문으로 직접 구현. 내부 동작이 블랙박스가 되지 않는다 |
| 실패를 숨기지 않음 | 동점 케이스를 억지로 통과시키지 않고 UNDECIDED -> FAIL로 정직하게 드러낸 뒤, 원인을 분류해 설명한다 |
| 측정 기반 설명 | O(N^2)를 말로 주장하지 않고, 크기별 10회 평균 실측 시간과 연산 횟수를 나란히 놓아 근거로 삼는다 |

## 2. 사용자

### 주요 사용자

- **누구**: 코디세이 3주차 학습자 본인 + 동료평가를 수행하는 동료
- **상황**: 터미널에서 `python main.py` 실행. 동료평가 시에는 README를 함께 열어 놓고 인터뷰
- **목표**: 학습자는 MAC/정규화/부동소수점/복잡도를 스스로 설명할 수 있게 되는 것, 동료는 요구사항 충족 여부를 5분 안에 확인하는 것

### 사용자 시나리오

**시나리오 A -- 직접 손으로 계산해 보기 (모드 1)**

1. 학습자가 터미널에서 `python main.py`를 실행하고 모드 1을 선택한다
2. 십자가 필터, X 필터, 그리고 X 패턴을 3줄씩 입력한다
3. A 점수 1.0 / B 점수 5.0 / 판정 B 를 보고 "곱하고 더하면 판별이 된다"를 확인한다
4. 일부러 `1 2` 처럼 2개만 입력하면 안내 문구가 뜨고 그 줄만 다시 입력하게 된다

**시나리오 B -- 큰 데이터 일괄 판정 (모드 2)**

1. 학습자가 모드 2를 선택한다
2. data.json에서 5x5, 13x13, 25x25 필터와 패턴 6건을 자동 로드/검증한다
3. 케이스별 Cross 점수 / X 점수 / 판정 / expected / PASS-FAIL이 순서대로 출력된다
4. 이어서 3x3~25x25 성능표와 총계(총 6 / 통과 3 / 실패 3)를 보고, 실패 사유가 "동점 규칙"임을 확인한다
5. 상세 원인은 README의 "결과 리포트" 섹션에서 읽는다

## 4. 사용자 흐름 (User Flow)

### 핵심 흐름

```
실행 -> 모드 선택 -+-> [모드 1] 필터 A 입력 -> 필터 B 입력 -> 저장 확인 -> 패턴 입력
                   |                -> MAC 연산 -> 판정 -> 성능 분석(3x3) -> 메뉴 복귀
                   |
                   +-> [모드 2] 필터 로드 -> 패턴 로드/검증 -> MAC/판정/PASS-FAIL
                                    -> 성능 분석(3x3, 5x5, 13x13, 25x25) -> 결과 요약 -> 메뉴 복귀
                   |
                   +-> [0] 종료
```

### 상세 흐름

1. **모드 선택**: `1` 사용자 입력(3x3) / `2` data.json 분석 / `0` 종료. 그 외 입력은 안내 후 재입력
2. **모드 1 - 필터 입력**: "필터 A (3줄 입력, 공백 구분)" 안내 후 3줄 수집. 각 줄은 숫자 3개
3. **모드 1 - 저장 확인**: 입력된 A/B 필터를 화면에 다시 출력해 저장 상태를 확인시킨다
4. **모드 1 - 패턴 입력**: 동일 방식으로 3줄 수집
5. **모드 1 - MAC/판정**: A 점수, B 점수, 10회 평균 연산 시간(ms), 판정(A/B/판정 불가) 출력
6. **모드 1 - 성능 분석**: 3x3 한 행짜리 성능표 출력
7. **모드 2 - 필터 로드**: size_5 / size_13 / size_25 각각 Cross, X 로드 완료 표시
8. **모드 2 - 패턴 분석**: 케이스별 Cross 점수 / X 점수 / 판정 / expected / PASS-FAIL 출력
9. **모드 2 - 성능 분석**: 3x3(내장 데이터) + 5x5 + 13x13 + 25x25 표 출력
10. **모드 2 - 결과 요약**: 총 테스트 수 / 통과 / 실패 + 실패 케이스 식별자와 사유

- [ ] 모드 2에서 6개 케이스 전부가 예외 없이 판정되고, 총계가 `총 6 / 통과 3 / 실패 3`으로 일치한다
- [ ] 판정과 expected 비교가 전부 표준 라벨(Cross/X) 기준으로 수행된다 (`+`, `x`, `cross` 원본값이 비교에 직접 쓰이지 않는다)

- [ ] `import numpy` 등 외부 라이브러리 import가 소스에 존재하지 않는다 (`json`, `os`, `time`만 사용)
- [ ] README "결과 리포트" 섹션이 10줄 이상이며, FAIL 3건의 원인을 데이터/로직/수치비교로 분류해 설명한다
- [ ] data.json을 삭제하거나 손상시켜도 프로그램이 트레이스백 없이 안내 메시지 후 메뉴로 복귀한다

## 6. 안 만드는 것 (Out of Scope)

> AI에게 코드를 시킬 때 이 목록을 함께 공유한다.

- **보너스 B1 (1D 배열 최적화)** -- 이유: 사용자 결정으로 이번 범위에서 제외. 필수 요구사항 충족과 코드 가독성을 우선한다
- **보너스 B2 (패턴 생성기)** -- 이유: 동일. 단, 모드 2의 3x3 성능 측정에 필요한 3x3 데이터는 "생성기"가 아니라 **고정 상수(BUILTIN)** 로 내장한다
- **GUI / 웹 화면** -- 이유: 과제 요구사항이 "Python 콘솔 애플리케이션 1개"로 명시됨
- **N x M 비정방 행렬 지원** -- 이유: 요구사항이 n x n 정방 행렬로 한정
- **필터 학습(학습 알고리즘)** -- 이유: 이번 미션은 고정 필터와의 유사도 계산까지가 범위. 역전파/가중치 갱신은 다음 단계 주제
- **stride / padding / 슬라이딩 윈도우 합성곱** -- 이유: 요구사항은 동일 크기 필터-패턴 1:1 MAC. 전체 CNN 합성곱은 범위 밖
- **data.json 쓰기(수정/저장)** -- 이유: 읽기 전용 분석 도구. 제출 데이터 원본을 보존해야 한다
- **로그 파일 출력** -- 이유: 요구사항은 콘솔 출력 + README 리포트. 파일 로깅은 검증 대상이 아니다

- [x] **epsilon 값** -- 요구사항 "권장 기준(예시)" 표기이나 8절 출력 예시가 `|A-B| < 1e-9`를 명시하므로 `1e-9`로 확정하고 상수화한다
